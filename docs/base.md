# Base

Hardware, installation, security and maintenance. Topic blocks: **Decision, Why, Not chosen, Where, Status.**

## Hardware

**Decision:** ThinkPad T14 Gen 2i, Intel Iris Xe, 1080p panel at scale 1.25, single monitor, keyboard driven tiling.
**Why:** It is the machine. Every size in `desktop.md` is chosen for 1.25 (and tested at 1.25 on 2026-11-09).
**Where:** `install/system.sh` (Intel drivers, sof-firmware), `config/hypr/modules/monitors.lua`
**Status:** done

## Installation (archinstall)

**Decision:**

| Option | Choice |
|---|---|
| Profile | Minimal (no desktop) |
| Disk | btrfs, default subvolumes (`@`, `@home`, `@log`, `@pkg`, `@.snapshots`) |
| Boot partition | archinstall default; 2 GiB when it can be set without manual partitioning |
| Bootloader | Limine |
| Encryption | LUKS on |
| Network | NetworkManager, iwd as Wi-Fi backend (see Network) |
| Audio | PipeWire |
| User | own user with sudo |

**Why:** Minimal leaves nothing to clean up; the repo installs the desktop. Limine boots snapshots through `limine-snapper-sync` and already boots this ThinkPad. The other choices are what the scripts assume.
**Not chosen:** Hyprland profile (adds SDDM, dunst, kitty, wofi, polkit-kde to remove later). Omarchy (too many decisions not ours, AI features). GRUB, systemd-boot.
**Where:** `overview.md`, Install steps; `docs/post-install.md`
**Status:** done. Limine cannot decrypt, so kernel and initramfs stay on the unencrypted boot partition (archinstall default with LUKS); Plymouth asks the password. The kernel line lives in `/etc/default/limine` as `KERNEL_CMDLINE[default]="..."` (the full line, not only the additions); apply with `sudo limine-mkinitcpio`. `/boot/limine.conf` is generated by `limine-entry-tool`, never edited. Check the first `cmdline:` in it still starts with `cryptdevice=` before rebooting.

## Network

**Decision:** NetworkManager with iwd as its Wi-Fi backend (`wifi.backend=iwd`). systemd-networkd disabled, wpa_supplicant masked, NetworkManager-wait-online disabled.
**Why:** archinstall leaves networkd (with the live ISO's `20-wlan.network`), iwd and wpa_supplicant all running next to NetworkManager; two daemons on `wlan0` made Wi-Fi drop every 2 s and crashed iwd. iwd is the one proven on this card. wait-online held the boot for 6 s and nothing needs the network before login. The Control Center keeps working through nmcli.
**Not chosen:** wpa_supplicant backend (default; fought with iwd). systemd-networkd + iwd without NetworkManager (Control Center depends on nmcli).
**Where:** `config/networkmanager/wifi_backend.conf` (copied with sudo to `/etc/NetworkManager/conf.d/`), `docs/post-install.md` step 4:

```bash
sudo cp config/networkmanager/wifi_backend.conf /etc/NetworkManager/conf.d/
sudo systemctl disable --now systemd-networkd.service systemd-networkd.socket NetworkManager-wait-online.service
sudo systemctl stop wpa_supplicant.service && sudo systemctl mask wpa_supplicant.service
sudo systemctl enable --now iwd.service && sudo systemctl restart NetworkManager
```

Never disable iwd: NetworkManager loses the card (`wlan0 unavailable`). If Wi-Fi does not reconnect, `nmcli device wifi connect <ssid> --ask`.
**Status:** done. Tested on 2026-11-10 (20/20 pings, boot userspace from 8.5 s down). Watch `coredumpctl list iwd` for a few days.

## Packages

**Decision:** `base.sh` runs a full upgrade before installing anything. Official repos with `--needed --noconfirm`; AUR through yay, interactive, PKGBUILD shown. AUR kept small: the original packages minus `anki-bin` and `mpd-mpris` (both moved to the official repos as `anki` and `mpd-mpris`), with `brave-origin-bin` in place of `brave-bin`, plus `limine-mkinitcpio-hook`, `limine-snapper-sync` and `postman-bin` (DevDojo course), minus `exercism` if it came from the AUR.
**Why:** Arch does not support partial upgrades. AUR code runs as you, so it is reviewed. A package that reaches the official repos leaves the AUR list.
**Not chosen:** paru (same thing, yay already known).
**Where:** `install/lib.sh`, `install/base.sh`, `install/apps.sh`, `install/backend.sh`
**Status:** done. Recount the AUR list after editing `install/backend.sh` and `install/system.sh`. Optional tidy: move `mpd-mpris` and `anki` from their own `pac` line in `install/apps.sh` into the `music` and `everyday` arrays.

## Snapshots

**Decision:** snapper + snap-pac on `@`, a snapshot before and after every pacman transaction. No timeline snapshots (`TIMELINE_CREATE="no"`, `snapper-timeline.timer` off); `snapper-cleanup.timer` prunes the pacman snapshots by number. Setup is manual, once:

```bash
findmnt /.snapshots          # must show @.snapshots, else stop
sudo umount /.snapshots && sudo rm -r /.snapshots
sudo snapper -c root create-config /
sudo btrfs subvolume delete /.snapshots
sudo mkdir /.snapshots && sudo mount -a && sudo chmod 750 /.snapshots
sudo snapper -c root create -d "clean install"
sudo sed -i 's/^TIMELINE_CREATE="yes"/TIMELINE_CREATE="no"/' /etc/snapper/configs/root
sudo systemctl disable --now snapper-timeline.timer
sudo systemctl enable --now snapper-cleanup.timer
```

Snapshots appear in the Limine menu through `limine-snapper-sync` (AUR); `limine-mkinitcpio-hook` (AUR) redeploys Limine after its own updates.
**Why:** A rolling release will break something eventually; a snapshot is the undo. Timeline snapshots would add up to 10 boot entries an hour.
**Not chosen:** Timeshift (snapper is closer to pacman via snap-pac). grub-btrfs (GRUB not chosen). Timeline snapshots.
**Where:** `install/system.sh`
**Status:** done. Snapshot boot entries work (tested 2026-11-10); the `limine-snapper-sync` service shows disabled but entries are still written. Keep the boot menu timeout above zero (it is 3), it is the way into a snapshot.
`snapper rollback` does not work with the archinstall layout; restore by booting a snapshot or renaming `@` from a live USB.

## Security

**Decision:**

| Area | Choice |
|---|---|
| Disk | LUKS, required (autologin depends on it) |
| Firewall | ufw: deny incoming, allow outgoing |
| Lock | hyprlock at 5 min idle and before suspend |
| Bar commands | argument lists only, never shell strings with outside text |
| Wi-Fi passwords | typed in the Control Center, sent to nmcli through stdin, never on a command line |
| Clipboard | history capped at 50, Super + Shift + C wipes it |
| Docker | ports always published on 127.0.0.1 (Docker bypasses ufw) |
| PostgreSQL | peer for local sockets, scram passwords for TCP |
| SSH | client used (GitHub, dojo); server installed with openssh, never enabled |
| Admin prompts | hyprpolkitagent (`desktop.md`, Polkit agent) |

**Why:** One stolen laptop or one open port is the realistic threat.
**Where:** `install/system.sh`, `install/backend.sh`, `config/hypr/`, `config/quickshell/WifiSection.qml`
**Status:** done. ufw active (checked 2026-11-10). PostgreSQL auth (`pg_hba.conf`) not yet checked.

## Updates

**Decision:** `sudo pacman -Syu` weekly, after reading archlinux.org news. `yay` for AUR afterwards. `paccache.timer` keeps three versions of each package.
**Why:** Small regular updates break less than rare large ones; snapshots cover the rest.
**Where:** `install/system.sh`
**Status:** done

## Recovery

| Symptom | Fix |
|---|---|
| Black screen or login fails | Ctrl + Alt + F2, log in, read `hyprctl configerrors` and `~/.local/share/hyprland/hyprland.log` |
| Login loops after boot | Ctrl + Alt + F2, `sudo systemctl disable sddm`, reboot, read `journalctl -b -1 -u sddm` |
| LUKS password asked in text, no boot screen | `plymouth` missing from `HOOKS` or placed after the encrypt hook, or `splash` missing from `/etc/default/limine`; fix, `sudo limine-mkinitcpio` |
| Boot hangs with no text | In the Limine menu press E, remove `quiet splash`, boot to see the messages |
| Lock crashed | Ctrl + Alt + F3, log in, `WAYLAND_DISPLAY=wayland-1 hyprlock`, back with Ctrl + Alt + F1 |
| Bar gone | Run `quickshell` in a terminal to see the file and line |
| Wi-Fi drops every few seconds | Two daemons on `wlan0`: `systemctl is-active wpa_supplicant iwd systemd-networkd` must read inactive, active, inactive (see Network) |
| Update broke the system | Boot the previous snapshot from the Limine menu |
