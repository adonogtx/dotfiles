# Desktop

Hyprland, the pill, login, lock, look and input. Topic blocks: **Decision, Why, Not chosen, Where, Status.**

## Compositor

**Decision:** Hyprland with the Lua config, split in modules: monitors, env, look, input, rules, binds, autostart, programs, theme. Each module loads in protected mode; a broken one is reported as a notification and the rest still loads.
**Why:** Hyprland 0.57 removed the old `.conf` format. Modules keep each concern small.
**Not chosen:** i3 (X11, IntelliJ glitches), Niri, Omarchy. Scratchpad (2026-11-23: never used, no key to send a window to it).
**Where:** `config/hypr/hyprland.lua`, `config/hypr/modules/`
**Status:** done. Dispatchers not in the upstream example (fullscreen, move window, resize mode, previous workspace) are isolated; check `hyprctl configerrors` on first start (clean on 2026-11-10). Under SDDM the session does not read `~/.zshrc`: `env.lua` puts `~/.local/bin` first in `PATH` (the `gus-*` binds failed without it), and `autostart.lua` runs `dbus-update-activation-environment --systemd --all` before starting user services (polkit, mpd-mpris, portals need `WAYLAND_DISPLAY`).

## Windows

**Decision:** Solid. No blur, no transparency. Rounding 10, gaps 6 inside and 12 outside, 1 px hairline border, one soft shadow, animations around 150 ms. No title bar buttons.
**Why:** Legible, light on the Iris Xe, calm and readable without effects.
**Not chosen:** Translucent windows or panels. hyprbars (plugins break on every Hyprland update).
**Where:** `config/hypr/modules/look.lua`
**Status:** done

## Login

**Decision:** Plymouth asks the LUKS password; SDDM then logs in automatically to `hyprland.desktop`. One password per boot. Boot and lock are two screens (Lock). The boot has no text at all, so nothing depends on fonts; every part is an image. Sizes in physical px on the 1920 x 1080 panel, colors from `theme.md` (Color: boot and lock): background `background.png`, a fixed 1920 x 1080 photo of Osaka Castle scaled to the screen, the same image as the lock (Lock), with bar black behind it as fallback; no logo; password field 360 x 56, radius 28, panel fill, 2 px border in line, no placeholder, its centre at y 840; dots radius 7 in label, 30 px centre to centre, the row centred in the field. After the password the field stays (it never fades out) and a loading bar shows inside it, centred: a track 296 x 4, radius 2, in line, and a fill 4 px high, radius 2, in label that grows from the track's left end (`bar-track.png`; the fill is drawn as `bar-fill-left.png` and `bar-fill-right.png`, 2 x 4 caps, around `bar-fill-middle.png` scaled to the width, rebuilt only when the width changes by a whole pixel, so the rounded ends never stretch), above the field and below the dots. The dots fade out 200 ms while the bar fades in 200 ms, on the same ease out as the field. The fill grows on time from width 0: fraction = 0.92 x (1 - exp(-t / 1.5)), t in seconds since the password was given, so about 45% at 1 s, 80% at 3 s, 87% at 4.5 s, then it holds near 92%; when Plymouth quits it takes the whole track. Wrong password: the bar fades out 200 ms and goes back to empty, the border turns red for 1.2 s and the dots start again from none. The field fades in 250 ms, ease out, starting 150 ms after the theme starts (computed in the script's refresh callback). No breathing. Silent boot: the kernel line in `/etc/default/limine` (`KERNEL_CMDLINE[default]`, full line) adds `quiet splash loglevel=3 systemd.show_status=auto rd.udev.log_level=3 vt.global_cursor_default=0`, so no text shows before Plymouth.
**Why:** The disk password already proves who you are; the lock screen protects the running session. The mitsuuroko (2026-11-19): "The Hōjō crest: three scales, strength layered step by step." The bar loops on time (2026-11-19, after the first reboot): Plymouth gets no boot progress while LUKS unlocks, so a progress-driven bar sat empty for seconds and Plymouth quit at two of three segments. The photo (2026-11-25): boot and lock share one picture, so the threshold looks the same both ways; it is fixed, not the `gus-wallpaper` choice, because Plymouth runs before LUKS unlocks and cannot read home. No logo over the photo (2026-11-25): the photo alone is calmer. The bar inside the field (2026-11-25, option B): with the photo alone the screen looked frozen while LUKS unlocks; inside the field it stays small and the field does not move, and it runs on time for the same reason as the 2026-11-19 bar. The filling bar (2026-11-25): the sliding piece did not read as loading; a fill that slows near the end reads as progress without claiming any. System tokens instead of matcha (2026-11-25): the field looked out of place over the photo; the system black fits.

## Fonts

**Decision:** WhiteSur light icons (`WhiteSur-light`), Apple cursor (`apple_cursor`), white variant, size 24, Adwaita (light) for GTK 3, prefer light for GTK 4. GTK belongs to the documents side and stays light; the system side (Quickshell) and the code side (terminal, editors) do not use GTK.
**Not chosen:** WhiteSur dark, Adwaita dark (until 2026-11-11, with Dark Solid). The black variant of the Apple cursor (until 2026-11-11: hard to see on the dark side).

Brave Origin follows `color-scheme` through `xdg-desktop-portal-gtk`. fuzzel's icon theme stays WhiteSur light; fuzzel runs only in dmenu mode (Super + C, Super + W), which shows no icons (checked on black 2026-11-18).
